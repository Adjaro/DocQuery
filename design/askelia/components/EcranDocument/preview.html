3. Chargement des diagnostics PMSI MCO

3.1 Périmètre

Le flux couvre les RUM transmis mensuellement par le DIM depuis le 01/01/2015. Les séjours en cours de codage sont exclus et repris au mois suivant.

3.2 Règles d'extraction

Le diagnostic principal (DP) est lu dans la table RUM_DIAG avec type_diag = 'DP' ; les diagnostics associés significatifs (DAS) avec type_diag = 'DA'. Les diagnostics reliés (DR) sont conservés dans une colonne dédiée.

Les codes CIM-10 sont normalisés (suppression du point, majuscules) avant jointure avec le référentiel ATIH de l'année de sortie.

Champ sourceChamp cibleRègle
RUM_DIAG.code_diagcondition_source_valueNormalisation CIM-10
RUM_DIAG.type_diagcondition_status_concept_idDP → 32902 ; DA → 32908
RUM.dt_sortiecondition_start_dateDate de sortie du RUM

3.3 Gestion des rejets

Un code absent du référentiel de l'année est rejeté vers la table rej_pmsi_diag avec le motif « CODE_INCONNU » ; le taux de rejet mensuel ne doit pas dépasser 5 %.

Les rejets sont rejoués après la mise à jour annuelle du référentiel CIM-10.

Quelle date est utilisée pour condition_start_date, et que se passe-t-il pour un code inconnu ?

C'est la date de sortie du RUM, et non la date d'entrée .

Un code absent du référentiel ATIH de l'année est écarté dans rej_pmsi_diag. Si plus de 5 % des lignes sont rejetées dans le mois, le chargement est suspendu .
